Notes from the sprint retro, written up for the people who weren't there (and for me in three months, when I've forgotten why we decided any of this).

The big one: the release took four days instead of one. Nobody was slacking. The problem was that three people were waiting on each other in a circle (I needed Sam's review, Sam needed the docs build, the docs build needed my fix). We only noticed on day three, when someone drew it on the whiteboard.

So we've agreed to do one thing differently: whoever is blocked says so in the channel the same day, not at the next standup. Not a new process. Just saying it out loud, sooner.

Second thing, smaller: the flaky docs build is now officially somebody's job (mine, this sprint). It's been "someone should look at that" for two months. Which means nobody looked at it.

Things that went well, because retros shouldn't only be complaints: the filesystem test rewrite landed without drama, the new contributor got a PR merged in their first week, and we actually kept the sprint scope for once.

Open question I didn't get an answer to: do we want to keep doing releases on Fridays? I don't, honestly. But I'm not the one doing the support rota.

That's it. Short retro, short notes.
