# Bundled data

`ai-style-patterns.json` is the AI style-patterns DB: patterns extracted from the maintainers' corpus of AI-generated documents at repo-root `data/write-like-me/` with the technique in `../references/technique.md` (see its maintainer note), in the format of `../references/db-schema.md` with `"kind": "ai"`. The corpus holds 46 documents in six registers: under `ai-generated/`, 30 documents from the GPT, Claude, and Gemini families across articles, reports, LinkedIn posts, talk abstracts, and an email thread split into eight files by conversation stage; under `skills/`, 16 snapshots of three of this repository's own agent-written skills (write-like-me, agent-experience, skill-evals — each SKILL.md and every reference, copied from the skills at commit 6685400) tagged with the register `docs`. The snapshots are frozen so that the DB's quotes and counts stay verifiable after the live skills change; a refresh copies the skills again rather than editing them. The shipped DB is sealed (db-schema.md, Sealing) and carries no corpus paths; the unsealed DB that `validate --corpus-dir` verifies is the git commit named in its `corpus.note`. Its rates are register-weighted (`corpus.register_weights`: article 4, docs 3, report 2, social 2, abstract 2, email 1 — db-schema.md, Register weighting), so that neither the 16 docs files (nearly half of the words) nor the 13 articles define every rate by word count alone; ranges, spreads and tiers stay unweighted.

Processing measures the input against both DBs in one run — `textstats.py measure INPUT --db USER_DB.json --db data/ai-style-patterns.json` — and uses this DB's rows as the AI-evidence column of the comparison table; an AI-only run measures against this DB alone (`../references/processing.md`, Single-DB runs). Its rows reference the built-in `ai_*` counters and statistics of `../scripts/textstats.py` where one exists and carry their own regex otherwise, so the counters remain the executable definitions; the DB adds the corpus rates, spreads, tiers, and verbatim evidence behind them, plus the `register_scope` fields, the per-register splits and model-split notes the counters cannot carry. The DB is refreshed by re-running extract mode over the corpus when a new model generation visibly shifts the distribution, corpus documents are regenerated, or the skill snapshots are renewed; the current DB is the third extraction (2026-10-07: the docs register added to the second extraction of 2026-09-09, recounted over all 46 documents, and trimmed to the rows that carry a machine tell — neutral statistics such as sentence length or bold density stay out, and quotes are capped at four per row).
