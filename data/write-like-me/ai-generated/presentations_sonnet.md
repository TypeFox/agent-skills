## 1. One Protocol, Any IDE: Bringing Real-Time Collaboration to IntelliJ and Beyond

Live, Google-Docs-style collaboration in VS Code or the browser is table stakes by now. But what about IntelliJ, or any IDE that isn't built in TypeScript? This talk walks through the OCT Service Process, a stdin/stdout JSON-RPC bridge that brings Open Collaboration Tools' encryption, session lifecycle, and Yjs-based document sync to any language or platform. Using the freshly released IntelliJ plugin as a running example, we'll cover authenticating and joining a session, handling peer join/leave and document events, and applying live edits without reimplementing the entire collaboration stack from scratch. If you've ever wondered how to add real-time multi-user editing to a JVM, native, or non-web app, this is the blueprint.

## 2. Do More With Less: A UI Toolkit Built for Humans and Coding Agents

When Microsoft deprecated VS Code's Webview UI Toolkit, extension authors lost their only theme-aware component set. We used the gap to rethink the constraints — and built Baukasten, a React library that renders natively across VS Code, Eclipse Theia, Electron, and the browser from one codebase, switching only a CSS import. Every component reads host theme tokens directly, so a panel inherits the user's color scheme and accessibility settings for free. The more interesting story: what a deliberately narrow styling API does for coding agents. With no open-ended `style` or `color` props to reason about, an agent's context budget goes to logic instead of guessing pixel values — backed by an agent skill that ships accurate props and zero invented APIs. This talk covers the design-token architecture, and what we've learned building component libraries for a world where a growing share of UI code is written by agents.

## 3. No Concrete Syntax Tree, No Problem: Architecting a Language Engineering Framework for Speed

Concrete syntax trees are quietly the memory hog of every language workbench — in our own projects, they've accounted for over 70% of a workspace's memory footprint. Fastbelt, our new Go-based language engineering framework, ships without one: tokens are zero-copy string slices linked directly to AST nodes, giving language servers the same text-to-model lookup a CST provides, minus the second tree. This talk walks through the bets behind Fastbelt's architecture — dropping the CST, a workspace-wide lock that lets builds run fully parallel (throughput scales from ~7MB/s to ~45MB/s across 16 cores), and an interfaces-only API design that refuses "protected method" escape hatches. We'll also show how putting benchmarks directly in CI turned a 30MB/s tokenizer into one doing 180MB/s, and why performance has to be a tested feature, not an afterthought.

## 4. The Agent Joins the Session: Real-Time Pair Programming With AI, Together

What happens when you invite a coding agent into a live, multi-person session instead of running it locally for one developer? We built the OCT Agent to find out: a bridge that connects any ACP-compatible agent — Claude Code, Codex CLI, Goose, OpenCode — into an Open Collaboration Tools session as a first-class participant, using the same protocol messages as human peers. This talk covers why we chose the Agent Client Protocol over MCP for true bidirectional communication, how the bridge is architected, and the UX questions we hit along the way: why a live-typing cursor for the agent was the wrong call, why a shared diff view fit the collaborative spirit better, and how a simple `@agent` chat channel changed how a whole team works with AI. We'll close with the open problem we're still chewing on: giving an agent full workspace context when it runs on a peer's machine instead of the host's.

## 5. Teaching Coding Agents Your DSL: A CLI, Skills, and Evals for Langium AI

Coding agents are remarkably capable — until you ask them to write in a DSL they've never seen in training data. This talk shares what we've learned building Langium AI, and the tooling we just shipped to close that gap: a `lai` CLI that scaffolds evaluation-ready Langium projects and generates baseline system prompts in minutes, agent skills that let CLI-based agents like Claude Code, Codex, Gemini, or OpenCode learn a DSL's syntax and semantics on demand, and a new evaluation framework with the ergonomics of vitest or jest — but scored semantically rather than pass/fail, with aggregation and run history built in. We'll walk through setting up a DSL-aware agent from scratch, writing evaluations that actually tell you whether it understood your language, and the meta trick of using the same eval system to benchmark different agents once equipped with DSL-specific skills.

## 6. Engineering, Not Magic: A Practical Framework for Building With AI

"AI-powered" has become a synonym for magic, which is a problem the moment you have to ship something reliable. This talk lays out a practical mental model for building AI into real systems, built around a distinction we think gets skipped too often: enriching existing systems with AI versus building genuinely autonomous agent loops. They look different from the outside, but underneath they share the same engineering concerns — enriching and retrieving context, decomposing tasks and combining results, interacting with an environment, and validating outcomes. We'll talk about why neither approach is plug-and-play, why "just add AI" isn't a strategy, and what actually changes about your engineering discipline when you move from static, verifiable workflows to systems that act on their own. No hype, no magic — just the questions worth asking before your team writes the first prompt.
